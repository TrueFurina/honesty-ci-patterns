# 把「诚实」做成一个能 exit 1 的 CI 门禁

> 一个 0 star 的研究项目，比大多数论文更值得学的东西

## 缘起

大多数项目对「夸大表述」零约束。README 里写「解决了 XX 问题」「性能提升 10 倍」，没人核对，没人拦截，写的人自己也不一定信。

`TrueFurina/marl-ecdsa` 是一个多智能体强化学习 + 区块链共识的研究项目，0 star，几乎没人看。但它里面藏着一套我认为比它的技术结论更值得被看见的东西：**一套把「诚实」从道德呼吁降维成可机验 CI 规则的基础设施**。

## 核心洞察：别指望语义理解，把「不诚实」具化成「已知口径的回潮」

第一直觉是「做个语义模型检测谎言」——不现实，也过度工程。这个项目做法相反：**它放弃通用语义检测，只拦「已知踩过的坑的回潮」。**

它维护一张硬编码短语表 `FORBIDDEN_PHRASES`，内容全是这个项目（及其前身 CTF-Agent）真实踩过的坑：

```
「真实水位 89%」「真实水位 100%」「自主 7/7」「解出数 16→26」「5→13」…
```

每一句背后都是一个真实的、曾经被误报过的夸大数字。判定机制是纯关键词 + 正则匹配——**拦不住措辞新颖的夸大**，但能可靠拦住「已知错误口径的复发」。

这个取舍是清醒的：**防的是「回潮」，不是「任意不诚实」。** 而回潮恰恰是最常见、最危险的那种——同一个数字被推翻后，半年后又在某篇文档里被当成真值引用。

## 三个设计巧思

### 1. 「提及 ≠ 使用」——别让诚实门禁封杀自我批评

最直接的反对意见：「那我复盘时怎么引用错误的旧数字？」很多诚实门禁死在这——它把「提到错误数字」也当违规，于是诚实的自我批评文档反而跑不过门禁。

解法极简单：**先删掉引号包裹的内容，再匹配。**

```python
# 先剥离 「…」「…」"…" '…'，再匹配
```

于是「已作废：真实水位 89%（曾被误报）」能通过——因为它在引号里，是**提及**；而一句不带引号声称「真实水位 89%」会 fail。**用引号引用作废口径做复盘是允许的，只有实际使用才违规。** 这一句话同时保住了诚实门禁和自我批评的自由。

### 2. 推翻台账：不删除，打标记

数字被推翻后怎么办？删除会丢历史，保留会误导。这个项目两者都不要——**保留原文，但打上「已作废/曾写作/已被取代」标记。**

`caliber_check.py` 维护一张 30+ 词的豁免标记表（作废、历史快照、已被取代、曾写作、原写作、勘误、禁用…）。命中行含任一标记 → 判「豁免」，不计失败；否则判「漂移」，`--strict` 下 exit 1。

于是「推翻台账」不是一份独立文档，而是**散布在文档中、由豁免标记标识的历史口径沉积层**。存量自证：「22 条命中全带『已作废』豁免标记，strict 下 0 未豁免」——**公布自己存量脏数据，是真实维护者的特征。**

### 3. 数字先进登记簿，后进文档

`number_registry.json` 是一份 189 条目的「口径白名单」：每条 = 结论 + 允许怎么写 + 数据源 + 期望样本量 + 权威数字 + 容差 + 状态。

判据不是「样本量等于 71」，而是「**落在登记簿出现过的取值集合内**」——因为项目并行存在多种合法样本量（收敛=71 / 消融=10 / 另一实验=60），写个集合外的数字就是「无出处口径」。**数字由脚本注册进登记簿，再由门禁反向校验文档，形成「登记 → 引用 → 校验」闭环。**

## 它自己记录了自己曾经失效

这是我认为最能体现诚实的地方。`caliber_check.py` 的 docstring 至今保留着「它三重失效、从未真正跑过」的历史判决书：

> 此前 4 步口径门禁只挂在未入库的 `.git/hooks/pre-commit`：换机、克隆、`--no-verify` 都会让它整体失效，而 CI 从不检查口径。

2026-09/10 两次改造才把它变活——把规则分层（公共规则入库、私有身份表不入库），让 CI 在无私有配置时依然完整。

**一个会记录自己门禁曾经失效的项目，比声称门禁一直有效的项目诚实得多。** CI 注释里那句「`--no-verify` 仍可绕过本地层，CI 只防 main 分支入口」——它知道门禁的边界在哪，并写了下来。

## 边界（它自己也承认的）

- **关键词黑名单泛化弱**：拦得住已知回潮，拦不住措辞新颖的夸大
- **本地 pre-commit 不跑 caliber_check**：口径漂移的阻断力目前只存在于 CI
- **权威源在仓库外**：`deliverables/` 那份是权威源不入库，克隆者拿到的是只读镜像——CI 校验得了镜像结构，校验不了权威源真伪
- **CI 只防 main 入口**，防不了作者本人

## 为什么这比技术结论更值得学

技术结论是「MARL + 区块链在某种假设下让合作率提升 7.9%」——这类结论一大把，复现门槛高，可信度依赖假设。

但「怎么让一个项目的对外数字可信」是**每个项目都面临、几乎没人工程化**的问题。这套方案的可移植性在于：它不需要模型、不需要语义理解，只需要一张会增长的「踩过的坑」清单 + 一道愿意 fail 的门禁。

**最讽刺也最诚实的一点**：这个项目在真实赛事平台上「自主 LLM 解出数为 0」，它把这一点写进了 README 的诚实声明。**它最强的能力和最弱处同时摆在明面上。** 一个把「自主解出 0」写在首页的项目，比一百个「性能提升 10 倍」的项目更值得信任。

## 可运行示例

四巧思的骨架实现：[](honesty_scan.py)

```bash
python honesty_scan.py ./docs --registry number_registry.json

# 更多用法
python honesty_scan.py ./docs --config rules.json      # 外部规则配置（覆盖/追加词表）
python honesty_scan.py ./docs --json                   # JSON 输出（供面板/脚本消费）
python honesty_scan.py . --init ci                     # 生成 GitHub Actions 门禁模板
python honesty_scan.py . --init precommit              # 生成 pre-commit 钩子配置
```

| 规则 | 实现位置 |
|---|---|
| ①只拦已知回潮 | `FORBIDDEN_PHRASES` 拒绝列表 |
| ②提及≠使用 | `_QUOTE_RE` 先剥引用再匹配 |
| ③推翻不删除 | `EXEMPT_MARKERS` 豁免作废行 |
| ④数字先登记 | `--registry` 加载后，裸数字未登记即报错 |

已测试：Windows GBK 控制台强制 UTF-8 输出，bad.md 命中 2 处（`approximately` + `TODO`），clean.md 全绿，rc 0/1 正确。
